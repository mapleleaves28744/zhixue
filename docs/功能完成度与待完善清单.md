## 当前主链路

```text
注册登录 → 创建课程 → 上传资料 → 解析 → 切片 → 向量化
→ 知识点抽取 → RAG → Wiki → Tutor → 资源
→ 练习 → 错题 → 诊断 → 画像/记忆 → 自进化 → 推荐 → Agent 日志
```

真实验收使用 `xiaomi_mimo / mimo-v2.5`，`fallback_used=false`。详见 `19_测试方案/13_真实LLM主链路与Next安全专项验收记录.md`。

## 现有功能优化建议（不新增功能）

本节只改善已经存在的链路，不把教师端、管理员端、PWA、MinIO、完整 GraphRAG、数字人或新的资源类型列入优化范围。优先级依据是安全与数据正确性、用户可感知速度、失败恢复、代码维护成本和演示稳定性。

### P0：先解决安全、可信度和关键链路稳定性

| 优化项 | 当前证据 | 建议动作 | 可验证目标 |
|---|---|---|---|
| Grounded QA 检索速度与引用质量 | Mock 样本 `retrieval_ms=2033`；Recall@5 100%，但严格引用精度 28.33%、覆盖率 40% | 对 `evidence_retrieval_service.py`、`hybrid_retriever.py`、`grounded_qa_pipeline.py` 分段计时；用 `EXPLAIN ANALYZE` 定位慢查询；只对公有模板按“课程 + 查询 + 语料版本”缓存候选集；先优化切片去重、source diversity 与引用选择，不增加新检索框架 | 先以固定 33 题、每题重复运行建立 P50/P95；Recall@5 不下降，检索 P95 再降低至少 30%；严格引用精度和覆盖率均提升，并补真实 Provider 人工正确率 |
| Agent SSE 与队列恢复一致性 | 历史回放到实时订阅存在窗口；入队失败返回 503；已有原子认领、孤儿任务恢复和内联兜底 | 统一以数据库 `sequence_no` 为游标，订阅后补拉一次；让排队、内联兜底、Worker 恢复共用同一状态机和幂等断言；错误提示区分 Redis 不可用、重复任务和 Worker 超时 | 重连不丢事件、不重复终态；同一任务只被一个执行器认领；Redis/Worker 故障测试有稳定、可解释结果 |
| 媒体访问令牌安全 | `/media-assets/{id}/file|launch` 仍接受原始 JWT 查询参数，可能进入日志、历史和 Referer | 现有播放/下载流程改用短期资源签名，或鉴权请求换取 Blob URL；统一 URL 生成入口并清理日志 | 浏览器地址、服务日志和 Referer 不出现登录 JWT；过期签名和跨用户访问均被拒绝 |
| 演示数据真实性 | `/courses` 仍有部分固定演示指标；不同文档曾混用 304/323/361/442/466 | 页面只显示真实值或明确“示例”；规模数字只从自动清单和最新验收读取；录屏固定使用已验收账号与课程 | 七个核心页面无伪装成实时数据的常量；文档检查能发现规模数字漂移 |

### P1：降低等待感和维护成本

| 优化项 | 当前证据 | 建议动作 | 可验证目标 |
|---|---|---|---|
| 助手页状态与副作用拆分 | `AssistantPageClient.tsx` 约 1130 行，流、课程、会话、任务、资源状态集中 | 保持 UI 和 API 不变，把课程切换、会话恢复、Tutor 流、Agent 流和资源面板状态拆入聚焦 hooks；用 reducer 明确请求所有权和终态 | 现有 Assistant 契约脚本全部通过；切课、停止、恢复、新会话无旧请求覆盖；主组件显著缩短 |
| Stitch 静态页请求治理 | `zhixue-static-api.js` 约 977 行，多个 500～1600 行 HTML 同时承载布局与业务脚本 | 不重做 React 页面；把鉴权、课程解析、loading/empty/error、请求取消和埋点抽为可复用静态模块，页面只保留编排 | 七个核心路由的 401、空数据、网络失败提示一致；重复请求与重复工具函数减少；Stitch 视觉不变 |
| 后端热点文件收敛 | `grounded_qa_pipeline.py` 约 816 行、`resource_service.py` 约 708 行、`profile_service.py` 与 `supervisor_intents.py` 均超 600 行 | 按“纯解析/策略/持久化/响应组装”拆分内部模块，保留现有 Service 公共接口；先加特征测试与事务边界测试再移动代码 | API/OpenAPI 零变化；466 项回归不减少；热点模块职责和循环依赖下降 |
| 生命周期与测试入口去歧义 | 全量测试有 FastAPI `on_event` 和 pytest-asyncio 默认 scope 警告；从仓库根直接跑后端测试会因模块路径失败 | 迁移到 FastAPI lifespan；显式设置 `asyncio_default_fixture_loop_scope`；提供根目录统一检查入口，内部固定 cwd 和解释器 | 全量 pytest 0 个相关弃用警告；从仓库根和 `backend/` 执行得到同一结果 |
| 文档数字单一事实源 | 当前活动文档曾出现 19+ migrations、54/61 测试文件及多个 pytest 总数 | 让比赛材料校验器从基线/自动清单读取 API、表、migration、Service、测试文件和 pytest 结果；历史验收文档按日期豁免 | 修改一个事实源即可发现所有活动文档漂移；历史记录不被误改 |
