## 录制前准备

1. 使用 1920×1080、100% 浏览器缩放、30fps 录制；关闭通知、开发者工具和无关标签。
2. 准备已验收的《数据结构》课程，确保能看到资料、Wiki、练习、画像、记忆、路径、自进化策略和一条完成的 Agent 会话。
3. 准备一条已经完成的沉浸课堂与 MP4 产物。录制时先现场提交同类任务，再切到这条已完成记录，画面加字幕“异步任务完成记录”，不要伪装成秒级生成。
4. 真实模型录制时展示 Provider 状态；Mock 环境在开场或助手段明确口播“当前为演示模式”。两种环境都不得隐藏 fallback，也不得用 Mock 结果宣称真实模型质量。
5. 提前登录一次验证 Token、当前课程和 API 地址；正式录制从退出登录后的品牌首页开始。
6. 清理画面中的 API Key、JWT、数据库地址和个人隐私。课程资料标题、引用和任务 ID 可以展示，用户隐私字段需要遮挡。
7. 录制前执行后端测试、前端构建或至少打开七个核心路由完成烟测。长耗时 AI 请求允许剪掉等待过程，但应保留“已提交”和“已完成”两个真实状态。

### 模型状态口播二选一

- 真实 Provider：`本次演示连接小米 MiMo 兼容模型，页面会保留真实 Provider 状态；历史 23 步主链路验收中没有回退 Mock。`
- Mock Provider：`本次使用无 Key 演示模式，重点验证完整工程链路和结构化输出，不把演示结果当作真实模型效果。`

正式录制时只保留与环境一致的一句。

## 七分钟逐字底稿

### 0:00–0:30　开场：我们解决什么问题

**画面**：品牌首页 `/`，鼠标依次指向项目名称、核心定位和登录入口；在 0:22 左右点击登录。

**旁白**：

> 大家好，我们的作品是“智学工坊”，面向中国软件杯 A3 赛题。高校学生常遇到三个问题：课程资料分散，通用 AI 的回答难以追溯，学习建议也很难根据长期表现持续调整。智学工坊把资料、问答、练习和诊断放进同一个个性化学习空间。它不是一个只回答一次问题的聊天机器人，而是一条可以持续沉淀、持续反馈的学习闭环。

**剪辑提示**：登录等待超过两秒时直接切到登录后的课程页，不展示账号密码。

---

### 0:30–1:20　课程与资料：建立可信知识底座

**画面**：`/courses` 在“我的课程与公共课程”真实列表中选中《数据结构》；不要口播原 Stitch Hero 的固定 `45% / 24 份 / 8 人`。进入 `/knowledge`，依次指向资料数量、解析状态、chunks、embeddings 和知识点统计。不要现场重新处理 32 份资料。

**旁白**：

> 登录后先进入课程空间。系统既支持学生创建课程，也提供只读的《数据结构》公共模板。当前验收知识库已入库三十二份资料，形成一千六百零八个切片和向量、一百二十五个知识点。资料会依次经过解析、切片、向量化和知识点抽取，每一步都有真实状态。检索始终限制在当前课程，先为后续 AI 输出建立可查的证据底座。

**操作**：打开一份已处理资料的详情，短暂停留在来源文件名和处理计数；随后切换到 Wiki 标签。

---

### 1:20–2:10　LLM Wiki：让知识可追溯、可积累

**画面**：`/knowledge` 的 Wiki 列表 → 打开一个“栈”或“二叉树”页面 → 展示摘要、正文、来源、版本历史，再切到关系图。

**旁白**：

> 在知识库之上，系统生成的是 LLM Wiki，而不是用完即失的摘要。每个页面都有结构化正文、来源、版本和知识关系。这里可以看到解释来自哪份资料；学生编辑、AI 补全或回滚时，旧版本仍然保留。页面还能表达前置、相似和易混淆等关系，让问答、错题、资源和诊断继续沉淀到同一个知识空间。这就是它和普通 RAG 对话最核心的区别。

**剪辑提示**：来源和版本各停留约三秒；关系图只做一次缩放，不花时间拖拽布局。

---

### 2:10–2:55　快速答疑：回答必须带依据

**画面**：进入 `/assistant` 快速模式，选择当前课程，输入“为什么栈适合做括号匹配？请基于课程资料回答并给出引用。”展示流式回答；展开一条引用。

**旁白**：

> 接下来进入 AI 学习助手。快速模式面向即时答疑。我询问为什么栈适合做括号匹配，并要求引用资料。系统先在当前课程做混合检索，再由可信问答流水线生成一次主回答。S1、S2 绑定真实资料和切片 ID，不合法的引用会被校验剔除；证据不足时，系统会明确说明，而不是强行作答。

**剪辑提示**：真实请求等待较长时保留问题提交和首个字出现，剪掉中间静止部分，并以小字幕标注实际等待时长。

---

### 2:55–3:50　智能体协作：过程可见、工具受控

**画面**：切换智能体模式，输入“基于课程资料，为二叉树前序遍历生成分步骤讲解和三道练习题。”提交后展示 queued/running；切到同一演示账号中已完成的对应会话，展开步骤时间线、工具详情、Review 和资源侧栏。

**旁白**：

> 当目标不只是一问一答时，可以切换到智能体模式。这个任务同时需要课程检索、分步讲解和练习生成。LangGraph Supervisor 会根据目标和执行观察动态选工具，再决定继续、审核或重新规划。系统有十五个 Agent 和二十四个受控工具；模型只能选择本轮候选工具，错误请求不会越权执行。前端把规划、调用、观察、审核和产物按时间线展示，详情中能看到状态、耗时和依据，右侧保留生成的讲解与练习。多智能体因此是有边界、有日志、可恢复的执行过程。

**剪辑提示**：不要等待现场任务全部完成；从新任务的真实 queued 状态切到已完成记录，并加字幕“同类异步任务完成记录”。

---

### 3:50–4:30　个性化沉浸课堂：长任务异步交付

**画面**：在智能体模式输入“为广度优先搜索生成个性化沉浸课堂和讲解视频”；展示任务卡后，打开已完成的课堂卡片和 MP4，播放五秒。

**旁白**：

> 对需要多模态表达的知识点，学生可以一句话发起个性化沉浸课堂。系统读取课程证据、画像、薄弱点和讲解偏好，再把受控任务交给二次集成的 OpenMAIC，完成后异步导出带配音字幕的 MP4。智学工坊负责权限、证据、个性化编排和产物管理；开源来源与许可证在仓库中保留。课堂播放使用短期签名，不直接暴露长期登录凭证。

**剪辑提示**：MP4 片段保持五秒左右，画面必须标注这是已完成产物，避免把异步任务说成即时生成。

---

### 4:30–5:20　练习与诊断：把结果反馈回学习过程

**画面**：`/practice` 打开一份练习，故意答错一题并提交；展示解析、错题记录和诊断摘要，再指向推荐练习主题。

**旁白**：

> 生成资源之后，学习进入练习和反馈。我故意提交一个错误答案，系统返回评分和解析，并记录错误标签、知识点和作答结果。诊断不是贴一个笼统标签，而是结合正确率、薄弱点和错误模式形成证据化结论。助手中最近提问的知识点也能成为练习推荐依据。问过什么、做错什么、下一步练什么，就连成了可解释链路。

**操作**：若现场生成诊断耗时较长，展示刚提交的记录后打开已有诊断报告；保留报告日期，避免冒充本次即时结果。

---

### 5:20–6:30　画像、记忆、路径与自进化：受控地越学越懂你

**画面**：`/path-profile` 依次展示全局画像、课程画像、对话证据、长期记忆和学习路径；随后进入 `/evolution`，打开一条策略详情，展示证据、风险等级、版本与回滚入口。

**旁白**：

> 这些行为最终回到学生画像。跨课程偏好进入全局画像，掌握度和薄弱点进入课程画像，并保留对话、答题或诊断证据。长期记忆按稳定键合并，重复内容只归档、不删除历史；Tutor 只读取当前课程最相关的少量记忆，避免上下文无限膨胀。学习路径再从薄弱优先、覆盖优先和难度梯度中选择方案。
>
> 最后看自进化。这里的“进化”绝不是修改代码、数据库结构或权限，而是受控调整答疑风格、资源策略、难度、推荐和路径参数。每条策略都有版本、证据、风险和状态；低风险策略可按规则生效，中高风险变化不会静默执行，已生效策略还能回滚。因此，系统能持续理解学生，又把变化限制在可解释、可记录、可恢复的范围内。

**剪辑提示**：画像证据、记忆来源和策略风险各停留三秒；回滚只展示入口或使用专门演示策略，禁止破坏正式演示账号状态。

---

### 6:30–7:00　总结：闭环与工程可信度

**画面**：回到 `/home` 学习总览，最后切回品牌首页；右下角叠加规模数字。

**旁白**：

> 从课程资料进入，到 Wiki 沉淀、可信答疑、资源生成、练习诊断，再到画像、记忆和策略更新，智学工坊完成了学生端学习闭环。当前代码包含一百四十七个 API、四十四张 ORM 表、二十四个数据库迁移、十五个 Agent 和二十四个工具；四百六十六项后端测试通过。真实 MiMo 主链路已有二十三步独立验收，无 Key 时也能用明确标注的 Mock 模式演示。以上就是我们的作品，感谢观看。

## 剪辑与真实性约束

1. 成片不要出现教师端、管理员后台、MinIO、完整 GraphRAG、数字人或其他尚未实现能力。
2. 旧验收数字只作为历史记录；成片统一使用 2026-07-13 活动基线：147 API、44 表、24 migration、15 Agent、24 工具、466 passed。
3. 真实 LLM 的 23 步主链路不能表述成“所有文本与媒体 Provider 全量通过”；全量 Provider 基线尚未建立。
4. AI 等待过程可以剪辑，但必须保留真实提交状态和真实完成记录，不用静态图冒充运行结果。
5. 每个关键 AI 结果至少露出一次来源、证据、Provider 状态、Agent 步骤或策略风险。
6. 最终成片建议保留三到五秒字幕：`Mock 仅用于无 Key 演示；真实效果以独立验收记录为准。`
