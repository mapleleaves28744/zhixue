>

本文是面向评委的逐字录制底稿，采用“学习闭环作叙事、工程证据作证明”的表达方式：每个能力点都必须同时出现学生价值和至少一项可见依据。录制前请先完成 [`录制前智能问答与产物准备清单.md`](录制前智能问答与产物准备清单.md)，不要在成片中等待长任务。

## 录制前准备

1. 使用 1920×1080、100% 浏览器缩放、30fps 录制；关闭通知、开发者工具和无关标签。
2. 使用已验收的《数据结构》课程；确认可访问资料、Wiki、助手、练习、画像、路径、自进化和一条完成的 Agent 会话。
3. 按“录制前智能问答与产物准备清单”生成并核验带引用的回答、已完成的 Agent 会话、练习/诊断、画像证据、沉浸课堂和 MP4。长任务录制时只保留真实“提交中”和同类“已完成记录”，并加字幕“异步任务完成记录”。
4. 真实模型录制时展示 Provider 状态；Mock 环境在开场或助手段只口播一次“当前为无 Key 演示模式”，不把 Mock 输出说成真实模型质量，也不隐藏 fallback。
5. 正式录制从品牌首页开始；提前验证登录、当前课程、引用展开、会话回放、课堂播放和视频文件可打开。
6. 遮挡 API Key、JWT、数据库地址和个人隐私；课程资料标题、引用和任务 ID 可展示。
7. 录制前运行可用的后端测试、前端构建或至少对七个核心路由进行烟测。AI 等待可以剪辑，但不能用静态页面冒充刚刚生成的结果。

### 模型状态口播二选一

- 真实 Provider：`本次演示连接小米 MiMo 兼容模型，页面会保留真实 Provider 状态；历史 23 步主链路验收中没有回退 Mock。`
- Mock Provider：`本次使用无 Key 演示模式，重点验证完整工程链路和结构化输出，不把演示结果当作真实模型效果。`

正式录制时只保留与环境一致的一句。

## 七分钟逐字底稿

### 0:00–0:35　开场：为什么不是普通聊天机器人

**画面**：品牌首页 `/`；鼠标依次指向项目名称、定位和登录入口，约 0:25 点击登录。

**旁白**：

> 大家好，我们的作品是“智学工坊”，面向中国软件杯 A3 赛题。高校学生面对的不是缺少资料，而是资料分散、AI 回答难以验证、学习记录无法持续影响下一步建议。我们把课程资料、可信问答、练习诊断和个性化策略放进同一个学习空间。它不是一次性聊天机器人，而是一套能沉淀知识、理解学习状态，并在受控边界内持续优化学习策略的系统。

**剪辑提示**：登录等待超过两秒，直接切到登录后的课程页；不展示账号密码。

---

### 0:35–1:25　资料到 Wiki：先建立可以追溯的知识底座

**画面**：`/courses` 选择《数据结构》公共课程，随即进入 `/knowledge`；展示真实资料、处理状态、切片、向量和知识点统计；打开一份资料后切到一个 Wiki 页面，露出来源、版本和关系。

**旁白**：

> 系统从课程资料开始。学生可以创建课程，也可以学习只读的《数据结构》公共模板。当前验收知识库已处理三十二份资料，形成一千六百零八个切片和向量、一百二十五个知识点。资料经过解析、切片、向量化和知识点抽取，并限制在当前课程范围内检索。
>
> 在此基础上，系统生成 LLM Wiki，而不是一次性摘要。每个页面保留结构化内容、来源、版本和知识关系；学生编辑、AI 补全或回滚都不会覆盖历史。这样，后续的问答、错题和资源都能沉淀回同一个知识空间，这也是它区别于普通 RAG 对话的第一层创新。

**剪辑提示**：不要解释 `/courses` Hero 中固定的 `45% / 24 份 / 8 人`，它们不是实时统计；来源、版本、关系各停留约两秒即可。

---

### 1:25–2:20　可信问答：答案、依据与速度同时可见

**画面**：`/assistant` 快速模式，输入预先准备问题“为什么栈适合做括号匹配？请基于当前课程资料回答，并给出引用。”展示提交、首个流式增量、S1/S2 引用并展开一条来源。

**旁白**：

> 接下来是即时答疑。我问“为什么栈适合做括号匹配”，并明确要求基于课程资料回答。系统先做当前课程范围内的混合检索，再通过 Grounded QA 流水线一次生成主回答。S1、S2 不是装饰性标记，而是绑定真实资料和切片的引用；不合法引用会被校验剔除，证据不足时系统会明确说明不能充分回答。
>
> 工程上，这条快速链路避免重复检索和重复生成，首个回答增量前才允许一次降级；前端还处理了停止接收、历史恢复和旧请求覆盖新会话等流式场景。因此，我们同时关注“回答有没有依据”和“学生能不能及时看到答案”。

**剪辑提示**：保留提交和第一个字出现；等待部分可剪，字幕标注实际等待时长。不要把无引用回答剪进这一段。

---

### 2:20–3:30　智能体：会协作，但不越权

**画面**：切换智能体模式，提交“基于当前课程资料，为二叉树前序、中序和后序遍历生成分步骤讲解，并附三道递进练习题。”展示真实 queued/running；切换到同一账号已完成的同类会话，展开步骤时间线、一次工具调用、Review 和练习产物。

**旁白**：

> 当任务需要多个步骤时，系统进入智能体模式。这条请求同时需要检索课程证据、组织讲解和生成练习。LangGraph 运行时由 Supervisor 根据目标与执行观察动态选择工具，再决定继续执行、审核，还是重新规划。
>
> 当前系统有十五个 Agent 和二十四个集中注册的工具，但模型不能任意调用：每轮只能从意图匹配的候选工具中选择；非候选工具请求会被安全改写或进入重新规划，不能越过 Tool Registry。前端按时间线展示规划、工具调用、观察、Review 和最终产物；任务、事件与会话可持久化和恢复。我们的多智能体不是概念堆砌，而是可观察、可审计、可恢复的受控协作。

**剪辑提示**：不等待现场任务完成。必须先录到真实 queued/running，再切到已完成同类记录，并始终保留“异步任务完成记录”字幕。

---

### 3:30–4:10　沉浸课堂：多模态也保持证据和安全边界

**画面**：在智能体模式提交“基于当前课程资料和我的分步骤讲解偏好，为广度优先搜索生成个性化沉浸课堂。”显示任务卡；打开已完成课堂卡片和导出的 MP4，播放约五秒。

**旁白**：

> 对需要更强交互和多模态表达的知识点，学生可以一句话发起个性化沉浸课堂。系统先读取课程证据、画像、薄弱点和讲解偏好，再将受控任务交给二次集成的 OpenMAIC，完成后可异步导出带配音字幕的 MP4。
>
> 这里的边界同样明确：智学工坊负责用户权限、课程证据、个性化编排和产物管理；OpenMAIC 负责课堂场景生成与播放。播放采用绑定课堂 ID 的短期签名，不直接暴露长期登录凭证。

**剪辑提示**：MP4 必须标注“已完成产物”；不得表述为秒级实时生成。

---

### 4:10–5:00　练习与诊断：让一次学习行为成为下一步依据

**画面**：`/practice` 打开已准备练习，故意答错一题并提交；展示解析、错题记录、已完成诊断和推荐主题。

**旁白**：

> 生成内容不是终点，系统还要确认学生是否真正掌握。我故意答错一道题，系统返回评分和解析，并记录错误标签、关联知识点和作答结果。诊断会结合正确率、薄弱点和错误模式形成可查看的结论；助手里最近提问的知识点也会进入练习推荐依据。
>
> 因此，从“我问过什么”，到“我做错什么”，再到“下一步应该练什么”，系统保留了一条可解释的反馈链，而不是随机推荐一组题目。

**剪辑提示**：诊断较慢时，展示本次提交后打开已有诊断报告；保留报告日期，不能声称它刚刚生成。

---

### 5:00–6:10　画像与自进化：越学越懂你，但绝不自动改系统

**画面**：`/path-profile` 展示全局画像、课程画像、对话证据、长期记忆和学习路径；进入 `/evolution`，打开一条策略的证据、风险、版本与回滚入口。

**旁白**：

> 这些学习行为最终进入学生画像。跨课程的偏好保存在全局画像，掌握度和薄弱点保存在课程画像，并能追溯到对话、答题或诊断证据。长期记忆按稳定键合并，重复内容归档但不删除历史；答疑时只加载当前课程最相关的少量记忆，避免上下文无限增长。
>
> 学习路径再从薄弱优先、覆盖优先和难度梯度等方案中选择。最后是自进化：它绝不修改源代码、数据库结构、权限或部署配置，而是受控调整答疑风格、资源策略、难度、推荐和路径参数。每条策略都有证据、风险等级、版本和状态；低风险变化按规则生效，中高风险不会静默执行，已经生效的策略还能回滚。这就是系统“持续个性化”与“可控可信”之间的平衡。

**剪辑提示**：画像证据、记忆来源、策略风险和回滚入口各停留两到三秒；不要在正式演示账号上真正执行回滚。

---

### 6:10–7:00　总结：从学习闭环到工程可信度

**画面**：回到 `/home` 学习总览，依次叠加“147 API / 44 ORM 表 / 24 migration / 15 Agent / 24 工具 / 466 passed”，最后回到品牌首页。

**旁白**：

> 从课程资料进入，到 Wiki 沉淀、可信问答、智能体协作、练习诊断，再到画像、记忆和策略更新，智学工坊形成了面向学生的完整学习闭环。当前代码包含一百四十七个 API、四十四张 ORM 表、二十四个数据库迁移、十五个 Agent 和二十四个工具，后端四百六十六项测试通过。
>
> 真实 MiMo 主链路已有二十三步独立验收；无 Key 时仍可使用明确标注的 Mock 模式完成工程演示。我们希望交付的不只是“能生成内容”的 AI，而是一个有依据、有边界、能长期服务学习过程的个性化学习空间。感谢观看。

## 剪辑与真实性约束

1. 成片不出现教师端、管理员后台、MinIO、完整 GraphRAG、数字人或其他尚未实现能力。
2. 统一使用 2026-07-13 活动基线：147 API、44 表、24 migration、15 Agent、24 工具、466 passed。
3. “23 步真实 LLM 主链路验收”不能说成所有文本与媒体 Provider 全量通过；全量 Provider 验收基线尚未建立。
4. 可以剪掉等待，但必须保留真实提交状态和真实完成记录；不能用静态截图伪装现场生成。
5. 每个关键 AI 结果至少出现一次来源/引用、Provider 状态、Agent 步骤或策略风险。
6. 最终成片建议保留三到五秒字幕：`Mock 仅用于无 Key 演示；真实效果以独立验收记录为准。`
