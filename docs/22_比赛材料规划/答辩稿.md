## 一分钟介绍

智学工坊面向高校学生，把课程资料转化为有来源、有版本、有关系的 LLM Wiki，并通过 15 个 Agent 协作完成问答、资源、练习、诊断、画像和学习策略更新。我们的自进化不修改代码，而是基于学习证据受控更新个性化策略，所有变化可解释、可记录、可回滚。当前系统有 **149** 个 API、48 张数据表、33 个数据库 migration；2026-10-12 强制 Mock 回归为 633 passed、2 failed，历史完整回归为 635 passed（2026-10-01）。

## 五分钟主线

1. **痛点**：资料分散、问答一次性、推荐缺乏依据、知识不沉淀。
2. **方案**：资料进入个人知识空间，形成「上传→Wiki→答疑→练习→诊断→画像→自进化→推荐」闭环。
3. **演示**：上传到 Wiki、Tutor/智能体、资源侧栏、连续追问与互动课件、练习诊断、画像自进化。
4. **创新**：LLM Wiki、受控自进化、可观察多 Agent、个性化闭环。
5. **工程**：FastAPI + PostgreSQL/pgvector + Next.js 16，真实 Provider 与 Mock 双链路，测试和迁移可运行。

## 技术创新回答

- **为什么不是普通 RAG？** 检索结果继续沉淀为可编辑、可追溯、可关联的 Wiki，并与练习诊断联动。
- **为什么需要多 Agent？** 不同任务拥有不同输入输出和校验边界，便于记录、解释和降级；LangGraph Supervisor 动态选工具，20/20 场景通过。
- **自进化是否危险？** 它只更新学习策略、画像和记忆，有证据、风险等级、版本和回滚，禁止修改代码或权限。
- **是否真实调用大模型？** 历史 MiMo 23 步主链路及 Qwen 连续上下文/记忆评测已有真实 OpenAI-compatible Provider 证据，`fallback_used=false`。
- **OpenMAIC 是什么？** 基于课程 RAG 和画像的历史沉浸课堂实现，保留播放与 MP4；当前默认停止新建，Agent 不提供课堂生成；源码以 AGPL 保留在 third_party，播放采用 HMAC 签名隔离。
- **个性化闭环做了什么？** 双层画像、记忆 stable key 合并、策略物化到 Prompt 参数、首页真实学习分析（learning_sessions 心跳）。
- **AI Coding 怎么用？** Cursor/Codex 辅助开发，但所有产出过 pytest/build/验收脚本；与运行时 Agent 一样不越权改代码/DB（见 AI_Coding工具使用说明）。

## 高频问题

| 问题 | 回答要点 |
|---|---|
| 数据如何隔离？ | JWT 当前用户、课程归属校验、查询带用户上下文；越权返回 404 |
| 没有 API Key 能否演示？ | 普通 Tutor、Wiki、资源、练习、诊断可使用 Mock；当前 LangGraph Agent 模式需要真实 Provider，不能把 Mock 说成完整 Agent 效果 |
| 当前最大缺口？ | 除全站 E2E、演示数据和 Docker 正式验收外，代码评估还确认 Review 阻断分支、未知在途写操作核对及本次 2 项 Mock 测试隔离失败、公共课程写权限和 Agent 无 Key 边界需要修复 |
| 管理员/教师端呢？ | 教师端冻结，管理员后台未实现，聚焦学生闭环 |
| 635 项测试覆盖什么？ | Auth、课程、资料、Wiki、Tutor、资源、练习、诊断、画像、Agent、OpenMAIC、练习推荐、联网搜索、权限等 |
| 为什么部分页面像静态页？ | 当前 Stitch 视觉原型 + 真实 API 接入策略；`/assistant`、`/evolution` 已 React 化 |
| GraphRAG / MinIO？ | 规划增强项，当前为 Hybrid RAG + 本地 storage，不宣称已实现 |
| 策略效果如何评估？ | 5 个相关行为或 7 天后生成待复核摘要；完整因果评估为后续增强 |

本次检查与历史证据的区别见 [文档同步复核记录](../19_测试方案/30_文档同步复核记录.md)。合成评测不等于真实学生学习收益。
