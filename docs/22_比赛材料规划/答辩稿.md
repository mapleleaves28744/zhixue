## 一分钟介绍

智学工坊面向高校学生，把课程资料转化为有来源、有版本、有关系的 LLM Wiki，并通过 14 个 Agent 协作完成问答、资源、练习、诊断、画像和学习策略更新。我们的自进化不修改代码，而是基于学习证据受控更新个性化策略，所有变化可解释、可记录、可回滚。当前系统有 143 个 API、44 张数据表、304 项后端测试通过。

## 五分钟主线

1. **痛点**：资料分散、问答一次性、推荐缺乏依据、知识不沉淀。
2. **方案**：资料进入个人知识空间，形成「上传→Wiki→答疑→练习→诊断→画像→自进化→推荐」闭环。
3. **演示**：上传到 Wiki、Tutor/智能体、资源侧栏、OpenMAIC 课堂、练习诊断、画像自进化。
4. **创新**：LLM Wiki、受控自进化、可观察多 Agent、个性化闭环。
5. **工程**：FastAPI + PostgreSQL/pgvector + Next.js 16，真实 Provider 与 Mock 双链路，测试和迁移可运行。

## 技术创新回答

- **为什么不是普通 RAG？** 检索结果继续沉淀为可编辑、可追溯、可关联的 Wiki，并与练习诊断联动。
- **为什么需要多 Agent？** 不同任务拥有不同输入输出和校验边界，便于记录、解释和降级；LangGraph Supervisor 动态选工具，20/20 场景通过。
- **自进化是否危险？** 它只更新学习策略、画像和记忆，有证据、风险等级、版本和回滚，禁止修改代码或权限。
- **是否真实调用大模型？** 已配置真实 OpenAI-compatible Provider（xiaomi_mimo / mimo-v2.5），23 步主链路验收，`fallback_used=false`。
- **OpenMAIC 是什么？** 基于课程 RAG 和画像的一句话生成个性化沉浸课堂，支持 MP4 导出；源码以 AGPL 保留在 third_party，播放采用 HMAC 签名隔离。
- **个性化闭环做了什么？** 双层画像、记忆 stable key 合并、策略物化到 Prompt 参数、首页真实学习分析（learning_sessions 心跳）。
- **AI Coding 怎么用？** Cursor/Codex 辅助开发，但所有产出过 pytest/build/验收脚本；与运行时 Agent 一样不越权改代码/DB（见 AI_Coding工具使用说明）。

## 高频问题

| 问题 | 回答要点 |
|---|---|
| 数据如何隔离？ | JWT 当前用户、课程归属校验、查询带用户上下文；越权返回 404 |
| 没有 API Key 能否演示？ | Mock Provider 可演示完整主链路；真实效果单独验收 |
| 当前最大缺口？ | 全站浏览器 E2E、一键演示数据、Docker 全栈正式验收 |
| 管理员/教师端呢？ | 教师端冻结，管理员后台未实现，聚焦学生闭环 |
| 304 测试覆盖什么？ | Auth、课程、资料、Wiki、Tutor、资源、练习、诊断、画像、Agent、OpenMAIC、权限等 |
| 为什么部分页面像静态页？ | 当前 Stitch 视觉原型 + 真实 API 接入策略；`/assistant`、`/evolution` 已 React 化 |
| GraphRAG / MinIO？ | 规划增强项，当前为 Hybrid RAG + 本地 storage，不宣称已实现 |
| 策略效果如何评估？ | 5 个相关行为或 7 天后生成待复核摘要；完整因果评估为后续增强 |
