## 统一调用边界

所有大模型请求必须经过 `backend/app/llm/provider.py` 的 Provider 抽象。业务 Service 和 Agent 不直接依赖厂商 SDK。当前支持 Mock 与 OpenAI-compatible Provider；真实链路已使用配置的 `xiaomi_mimo / mimo-v2.5` 验收。

当前代码存在 `prompt_versions` 数据模型和 `PromptService`，但没有独立 `backend/app/prompts/` 模板目录。后续新增提示词应优先进入版本化存储或统一模板目录，禁止继续散落。

## 场景提示词

| 场景 | 目标输出 | 必须提供的上下文 |
|---|---|---|
| Tutor | 回答、引用、关联知识点 | 当前问题、课程、检索片段、学生画像 |
| Wiki | 标题、摘要、正文、来源、关系建议 | 资料片段、知识点、已有页面 |
| 知识抽取 | 知识点和关系 | 文档切片、课程范围 |
| Resource | Markdown 学习资源 | 目标知识点、难度、学习偏好 |
| Quiz | 题干、选项、答案、解析 | 课程知识点、难度、薄弱点 |
| Diagnosis | 薄弱点、错因、建议 | 作答、错题、历史表现 |
| Evolution | 策略变化、证据、风险 | 画像、记忆、诊断、当前策略 |
| Review | 质量结论、问题、风险 | 生成结果、来源和任务目标 |

## 结构化输出与校验

- 提示词应要求可解析 JSON 或明确字段，Service 负责转为 Schema。
- 重要内容必须带来源；无可靠来源时标记 AI 推断。
- Quiz、诊断、策略等结果需规则校验或 Review Agent 检查。
- Provider 失败可回退 Mock 用于普通演示；真实验收禁止回退。

## 版本和日志

提示词版本应记录场景、版本号、状态与内容；LLM 调用记录 provider、model、token、latency、status 和脱敏错误。后续重点是让所有场景显式绑定 prompt version，并补充质量对比指标。
