## 角色边界

- **学生**：访问自己的课程、资料、Wiki、问答、练习、诊断、画像、记忆和策略。
- **管理员角色**：当前仅在少量既有接口中保留权限分支，没有独立后台。
- **教师端**：当前冻结，不建设教师业务页面和学生个人数据访问。

## 学生端主流程

```text
注册登录 → 创建课程 → 上传资料 → 解析/切片/向量化 → 抽取知识点
→ 生成 Wiki → Tutor 问答 → 生成资源 → 生成并完成练习
→ 诊断 → 更新画像/记忆 → 生成自进化策略 → 推荐下一步
```

页面承载：课程在 `/courses`，知识流水线在 `/knowledge`，问答与资源在 `/assistant`，练习诊断在 `/practice`，画像与策略在 `/path-profile`。

真实验收采用“浏览器交互 + HTTP 专项脚本”双证据：浏览器验证登录、路由和 Tutor 交互，真实 MainChain 验证资料至推荐的 23 步数据闭环。完整点击式浏览器 E2E 仍为增强项。

## 多智能体协作

Service 发起任务，Orchestrator 选择 Agent；Agent 通过 Service/Tool 获取上下文并调用统一 LLM Provider；Review Agent 或规则校验关键输出；执行结果写入 `agent_runs`。

## 用户旅程与异常处理

- 未登录访问业务页时，引导回品牌首页认证弹窗。
- 无课程或无资料时展示真实空状态，不伪造示例结果。
- LLM 不可用时允许 Mock Provider 演示，但真实验收必须拒绝 Mock 回退。
- 资料、Wiki、诊断等操作失败时保留可重试状态和错误提示。
