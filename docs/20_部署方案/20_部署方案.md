## 运行架构

### 本地开发（默认）

日常功能开发以本机服务为准，不依赖 Docker：

```text
浏览器 → Next.js :3000 → FastAPI :8000 → PostgreSQL + pgvector :5432
                                     └→ Redis :6379 → arq Worker
```

`/assistant` 的统一 Agent 任务依赖独立 arq Worker；只启动 FastAPI 会使异步任务无法被正常消费。无真实模型密钥时，`LLM_PROVIDER=mock` 与 `EMBEDDING_PROVIDER=mock` 可用于演示主链路。

### 服务器 Docker Compose

`docker-compose.prod.yml` 当前会启动以下服务：

| 服务 | 作用 | 默认对外端口 |
|---|---|---|
| `nginx` | 前端、API、文档和课堂反向代理 | `80` |
| `frontend` | Next.js 生产构建 | 仅容器网络 |
| `backend` | FastAPI；启动时执行 Alembic migration | 仅容器网络 |
| `worker` | arq Agent 后台任务 | 不对外暴露 |
| `postgres` | PostgreSQL 17 + pgvector | 不对外暴露 |
| `redis` | Redis 7 | 不对外暴露 |
| `openmaic` | 沉浸课堂引擎 | `3001`（排错用） |

Nginx 将 `/api/`、`/docs`、`/openapi.json`、`/health` 代理到 FastAPI；将 `/classroom/` 等课堂播放路径代理到 OpenMAIC；其余路径代理到前端。生产环境建议只向公网开放 `80/443`，并通过防火墙限制 `3001` 仅供运维排错使用。

## 部署前准备

1. 准备 Linux 服务器、Docker Engine 与 Docker Compose v2，并确保当前用户有 Docker 使用权限。
2. 准备域名和 HTTPS 终止层。仓库内 Nginx 当前只监听 HTTP `80`，证书、`443` 监听和域名跳转由服务器前置反代或后续部署专项配置负责。
3. 克隆仓库后，确认以下文件存在：

```text
docker-compose.prod.yml
deploy/nginx/nginx.conf
backend/Dockerfile.cloudrun
frontend/Dockerfile.cloudrun
third_party/openmaic/
```

4. 确保服务器磁盘空间足以容纳 Python/Node 镜像、Hugging Face 模型缓存、PostgreSQL 数据卷、上传资料和课堂媒体文件。
5. 不要提交 `.env`、模型 Key、JWT Secret、数据库口令或真实学生数据。

### 配置环境变量

从模板复制并限制读取权限：

```bash
cp .env.example .env
chmod 600 .env
```

服务器 `.env` 至少应修改以下值；示例中的密钥均为占位符，必须替换为随机强值或真实服务凭据。

```env
APP_ENV=production
DEBUG=false

POSTGRES_USER=zhixue
POSTGRES_PASSWORD=replace-with-a-long-random-db-password
POSTGRES_DB=zhixue
REDIS_DB=0

JWT_SECRET=replace-with-a-long-random-jwt-secret
BACKEND_CORS_ORIGINS=https://learn.example.com
NEXT_PUBLIC_API_BASE_URL=https://learn.example.com/api/v1
HTTP_PORT=80

OPENMAIC_ENABLED=true
# 容器内服务地址由 docker-compose.prod.yml 固定覆盖为 http://openmaic:3000
OPENMAIC_PUBLIC_BASE_URL=https://learn.example.com
OPENMAIC_INTERNAL_TOKEN=replace-with-a-long-random-service-token
OPENMAIC_SIGNING_SECRET=replace-with-a-different-long-random-signing-secret

# 无真实模型时保留 mock；真实演示再填入对应 Provider 配置
LLM_PROVIDER=mock
LLM_MODEL_NAME=mock-learning-model
EMBEDDING_PROVIDER=mock
EMBEDDING_MODEL=mock-embedding
EMBEDDING_DIMENSION=1024
```

真实 MiMo / OpenAI-compatible 模型、TTS、ASR 或文生图能力须按 `.env.example` 填写各自 Key、Base URL 和模型名。OpenMAIC 不会自动复用 `LLM_API_KEY`，真实沉浸课堂需显式设置 `XIAOMI_*`、`TTS_XIAOMI_MIMO_*` 与 `ASR_XIAOMI_MIMO_*`。无这些密钥时，其他主链路仍可使用 Mock；不要将 Mock 结果描述为真实模型效果。

`DATABASE_URL` 与 `REDIS_URL` 在服务器 Compose 中会被服务定义覆盖为容器内的 `postgres`、`redis` 地址；不要在 `.env` 中把它们写成 `localhost` 后期待容器内可用。

## 本地开发运行

本地默认连接本机 PostgreSQL / Redis：

```env
DATABASE_URL=postgresql+asyncpg://zhixue:zhixue_password@localhost:5432/zhixue
REDIS_URL=redis://localhost:6379/0
```

在项目根目录创建 `.env` 后，分别启动后端、Worker 与前端：

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

另开一个终端：

```bash
cd backend
source .venv/bin/activate
python -m arq app.workers.agent_worker.WorkerSettings
```

再另开一个终端：

```bash
cd frontend
npm install
npm run dev -- --hostname 127.0.0.1 --port 3000
```

访问 `http://127.0.0.1:3000`，后端健康检查为 `http://127.0.0.1:8000/health`，OpenAPI 为 `http://127.0.0.1:8000/docs`。Windows PowerShell 可使用 `scripts/start_phase31_demo.ps1` 一次启动 FastAPI、Worker、前端和 OpenMAIC；详情见本目录的本地开发指南。

根目录的 `docker-compose.yml` 是开发期 Compose 配置，挂载源代码并启动开发服务器；它不等同于生产部署配置。服务器请使用下文的 `docker-compose.prod.yml`。

## 服务器 Docker 部署

在仓库根目录执行：

```bash
docker compose -f docker-compose.prod.yml config
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps
```

首次构建会下载 Python、Node、pgvector、Redis 镜像及后端依赖，耗时取决于网络和机器配置。`backend` 的启动命令会先运行 `alembic upgrade head`，因此迁移失败时后端不会正常提供服务；不要绕过迁移后手工改表。

查看启动日志：

```bash
docker compose -f docker-compose.prod.yml logs --tail=100 postgres
docker compose -f docker-compose.prod.yml logs --tail=100 backend
docker compose -f docker-compose.prod.yml logs --tail=100 worker
docker compose -f docker-compose.prod.yml logs --tail=100 frontend
docker compose -f docker-compose.prod.yml logs --tail=100 openmaic
docker compose -f docker-compose.prod.yml logs --tail=100 nginx
```

更新代码后的推荐流程：

```bash
git pull
docker compose -f docker-compose.prod.yml build backend worker frontend openmaic
docker compose -f docker-compose.prod.yml up -d backend worker frontend openmaic nginx
docker compose -f docker-compose.prod.yml ps
```

不要使用 `docker compose down -v` 进行普通更新；该命令会删除 PostgreSQL、Redis 和模型缓存卷。仅在确认要清空全部数据时才可使用，并应先完成备份。

## 数据库迁移与演示数据

### 迁移

生产 Compose 已在 `backend` 容器启动时执行 `alembic upgrade head`。如需人工确认当前数据库版本，可运行：

```bash
docker compose -f docker-compose.prod.yml exec backend alembic current
docker compose -f docker-compose.prod.yml exec backend alembic upgrade head
```

### 初始化公共《数据结构》知识库

项目提供 `scripts/init_public_data_structure_kb.py`。生产 backend 镜像的构建上下文是 `backend/`，不包含根目录 `scripts/` 与 `data/`；因此用 Compose 临时挂载整个仓库执行脚本：

```bash
docker compose -f docker-compose.prod.yml run --rm --no-deps \
  -v "$PWD:/workspace" -w /workspace backend \
  python scripts/init_public_data_structure_kb.py --use-mock-embedding
```

该命令创建或更新课程代码 `DS-PUBLIC` 的公共《数据结构》课程，并导入资料、切片、知识点等内容。`--use-mock-embedding` 仅用于无真实嵌入模型的演示；若要求真实向量，请先配置嵌入 Key，再改用：

```bash
docker compose -f docker-compose.prod.yml run --rm --no-deps \
  -v "$PWD:/workspace" -w /workspace backend \
  python scripts/init_public_data_structure_kb.py --require-real-embedding
```

加 `--rebuild` 会重建该公共课程关联的资料和知识点，可能影响当前课程内容；仅在明确需要重建时使用。

### 初始化完整演示学生数据

以下命令会创建或重建演示学生及其课程、Wiki、练习、诊断、推荐、学习事件和图谱数据：

```bash
docker compose -f docker-compose.prod.yml run --rm --no-deps \
  -v "$PWD:/workspace" -w /workspace backend \
  python scripts/init_demo_student_data.py
```

脚本会在终端输出演示用户名、密码和课程 ID。默认会重建同名演示数据；若只想保留现有用户并刷新演示课程，使用 `--keep-existing`。演示数据仅适用于比赛或测试环境，生产环境不得使用公开演示账号。

## 部署后验收

按以下顺序检查，全部通过后才能记录为该服务器的 Docker 全栈验收：

```bash
curl -fsS http://127.0.0.1/health
curl -fsS http://127.0.0.1/openapi.json > /dev/null
curl -fsS http://127.0.0.1:3001/api/health
docker compose -f docker-compose.prod.yml ps
```

然后在浏览器检查：

1. 打开首页，注册或使用演示账号登录；
2. 确认 `/courses`、`/knowledge`、`/assistant`、`/practice`、`/dashboard`、`/path-profile` 可访问；
3. 选择课程后完成一次资料检索或 Tutor 问答，确认 API 请求经 `/api/v1` 成功返回；
4. 发起一次 Agent 任务，确认 `worker` 日志中有消费记录、页面可收到最终结果；
5. 若启用 OpenMAIC，生成或打开一节沉浸课堂，确认 `/classroom/` 的播放资源可加载；
6. 执行公共知识库或演示学生初始化后，确认页面展示的课程、Wiki 和练习来自真实接口而非静态占位内容。

可额外进行配置静态校验：

```bash
docker compose -f docker-compose.prod.yml config
```

当前基线明确标记“Docker 全栈正式验收”尚未完成。本节步骤是首次部署所需的验收清单；未实际执行前，不应在比赛材料中宣称 Docker 已验收通过。

## 运维与安全

- 数据持久化卷为 `postgres_data`、`redis_data`、`model_cache`；上传文件位于宿主机 `./storage`，课堂数据位于 `./third_party/openmaic/data`。这些路径应纳入备份策略。
- 数据库可在维护窗口通过 `pg_dump` 备份；恢复前需确认 PostgreSQL/pgvector 主版本兼容，并先在非生产环境验证。
- `.env` 与备份文件含敏感信息，应限制文件权限和访问范围；不要写入 Git、日志或截图。
- `OPENMAIC_INTERNAL_TOKEN` 与 `OPENMAIC_SIGNING_SECRET` 必须不同且足够随机。前者保护内部生成接口，后者用于课堂播放短期签名。
- 对公网部署时，配置 HTTPS、限制 SSH、设置防火墙，并避免公开 PostgreSQL、Redis 和 OpenMAIC 的调试端口。
- 容器日志可用 `docker compose ... logs` 查询；当前项目尚未配置集中日志、指标告警、自动备份、模型成本统计或完整 HTTPS 配置，这些属于后续部署专项工作。

## 常见问题排查

| 现象 | 优先检查 | 处理方式 |
|---|---|---|
| `backend` 持续重启 | `docker compose ... logs backend` | 检查 Alembic 报错、数据库健康状态及 `.env` 中必填变量；修复后重新启动 backend。 |
| Agent 任务一直 `queued` | `docker compose ... logs worker` | 确认 `worker` 运行、Redis 健康，且 backend/worker 使用同一 `REDIS_URL`。 |
| 页面请求到错误 API | 浏览器网络请求与 `NEXT_PUBLIC_API_BASE_URL` | 该变量在前端构建阶段注入；修改后必须重新 `build frontend` 并重启。 |
| 容器内连不上数据库或 Redis | backend/worker 环境变量 | 生产 Compose 内应使用 `postgres`、`redis` 服务名；不要使用宿主机 `localhost`。 |
| `alembic upgrade head` 失败 | backend 日志与 migration 版本 | 不要手工修改业务表；先修复连接、迁移冲突或依赖问题，再重新执行迁移。 |
| 上传文件失败 | Nginx 日志、磁盘和 `storage` 权限 | Nginx 已设 `client_max_body_size 55m`；同时确认上传限制默认 `MAX_UPLOAD_SIZE_MB=50`，以及 `./storage` 可写。 |
| 课堂播放 404 或签名失败 | `openmaic`、`backend` 日志和公开地址 | 确认 `OPENMAIC_PUBLIC_BASE_URL` 是浏览器可访问的 HTTPS/域名地址，且两项 OpenMAIC 密钥在 backend 与 openmaic 环境中一致。 |
| 首次构建超时或依赖下载慢 | Docker 构建日志与服务器网络 | 后端镜像已配置镜像源和较长超时；确认服务器可访问镜像/依赖源后重试。 |
| 需要重置演示环境 | 备份和目标范围 | 先备份数据，再使用演示脚本的重建选项；不要对未知环境执行 `down -v`。 |
