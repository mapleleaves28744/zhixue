### 3. 目标调用链与职责

```text
接收消息：认证、会话与课程访问校验、持久化原文与用户显式选项
  → ConversationContextService：固定本轮历史边界，读取最近完整回合与会话焦点
  → TurnContext：本轮原文、历史、已选对象、会话目标、精简画像
  ├─ 快速问答/改写：解析已有明确指代 → 需要时检索课程依据
  │    → 可选相关记忆 → ContextBuilder → 单次回答生成 → 引用规则校验
  └─ Agent/复杂目标：按需理解并建立 TaskContract → 可选相关记忆
       → ContextBuilder → Supervisor 原生 function calling
       → Registry/Service 校验、执行、更新子任务 → 继续/重规划/Review
  → 统一完成回合并返回结果
  → 有价值的已提交学习事件创建持久反思工作 → 后台抽取 → 校验与合并
```

这里是两条可选择路径，不能把图中所有模块强制串联到每一句话。IntentService 是共享语义解释能力：仅在模糊指代、组合任务或关键槽位不清楚时调用模型；快速问答不会固定先经过一个分类模型。服务端创建轻量本轮契约即可记录普通 QA 的约束，只有多步/多产物任务需要完整子任务账本。业务完成、事件落库与后台工作登记的事务边界见第 6、11 节。

意图理解可以读取当前选中的课程/资料/产物与最近消息；“刚才那个”必须绑定真实对象 ID。旧偏好不能覆盖本轮明确要求。长期记忆不作为课程事实引用，课程答案仍走现有 GroundedQAPipeline/RAG/Wiki 引用校验。

Agent 只产出结构化建议。MemoryService 管理事务与业务规则，MemoryRepository 管理查询；把当前 MemoryAgent 内查询、推进水位、commit 移到 Service/Repository，符合项目分层。所有解析、摘要和提炼走现有 LLM Provider，Prompt 进入 `backend/app/prompts/` 并版本化。

### 4. 意图识别契约与执行规则

#### 4.1 IntentFrame v1（拟新增 Pydantic 契约）

| 字段 | 约束与含义 |
|---|---|
| schema_version / request_message_id / revision | 版本为 v1；原始请求 ID；追问修订号 |
| mode | answer、execute、clarify；安全确认另用现有 waiting_confirmation，不混用 |
| tasks[] | 最多 8 个 Subtask；超限请求分批协商，不静默截断 |
| Subtask.id / action | 独立 ID；action 枚举如 answer_question、generate_quiz、generate_resource、update_profile、recall_history、manage_memory、apply_strategy |
| topic / knowledge_ids / target_refs | 用户主题、经服务校验的知识点 ID、资料/上一轮产物引用；模型输出的 ID 必须验归属和存在性 |
| constraints[] | key、value、source_message_id、source_span、origin；origin 区分 explicit_user、ui_selection、inferred、default、memory |
| depends_on[] / acceptance | 有向无环依赖；题数、题型、产物类型、可访问 artifact ID、来源要求等可验证条件 |
| exclusions / grounding | 不要做的动作；grounding 为 course_required、web_required、course_and_web、optional，支持混合检索 |
| unresolved_slots / clarification_question | 缺少的关键槽位；一次只问阻碍执行的问题 |
| parser / model / prompt_version / uncertainty | 解析来源与版本、枚举不确定原因；模型自报置信度只用于诊断，不能充当安全保证 |

例如“基于刚才的资料，栈和队列各出 5 道选择题，不要课件”：生成两个 generate_quiz 子任务，分别绑定栈和队列、同一已验证 material_id、count=5、题型 single_choice、grounding=course_required；排除 generate_interactive_courseware。两个子任务必须各有独立产物，不能因 generate_quiz 已成功一次就结束。

#### 4.2 路由方式

1. 确定性入口只处理 UI 明确操作、精确命令和完整匹配的简单寒暄。历史存在待答澄清时，“好”“继续”优先解释为上下文回复，不走寒暄分支。
2. 快速模式中的完整问题和明确改写请求直接走 QA；UI 显式动作使用其已知契约。Agent 模式交给现有模型工具循环，组合目标/关键歧义才启用一次结构化理解；新生成的多个交付动作必须先有可验证契约再执行。现有关键词仅为软候选和 Mock fallback，不是授权或强制工具选择条件。记录选择该路径的原因，未知请求允许澄清，不建立无限增长的关键词分类树。
3. 追问补全、意图解析共享一次语义结果（原文、resolved_query、引用对象、约束、子任务）；同一轮最多一次额外理解调用，schema 错误最多一次修复。简单课程问答只做一次回答生成；复杂任务允许理解后进入 Supervisor 工具循环，但不能再单独调用 query rewrite。IM-06 用调用计数和正确率决定是否把复杂理解合入首轮 Supervisor，首版不强制实现这一融合。契约可测性来自显式结构与校验，不要求每条请求额外调用一个模型。
4. 每个约束绑定来源并记录生效范围。教学呈现参数的优先级为本轮显式要求 > 同会话仍有效的显式要求 > 当前课程已确认偏好 > 全局已确认偏好 > 推断建议 > 产品默认值；均不能覆盖系统安全边界或直接改写需审核的策略。风险等级由服务端工具元数据和实际参数评估；模型不得降级风险。权限依赖及自进化中高风险确认规则继续由服务端执行。
5. 澄清首版复用现有会话消息：完成本轮询问，在 `AgentConversation.extra_meta.intent_draft_v1` 保存 draft、原始请求 ID 和修订号；下一条消息合并后生成新任务。不把缺失信息当执行失败，也不复用“批准高风险”的 resume API。草稿遇到明确换题、换课程、取消或完成即失效；同会话并发用 revision 校验，避免覆盖。
6. `tool_hints` 仅保留显式 UI 选择，新增 `inferred_tool_candidates` 存规则建议；两者都须验证注册、可用性和权限。未知意图先提供允许的只读工具和能力说明，允许 Supervisor 请求扩展候选工具；扩展仅在已授权全集内，不因候选漏召回直接改用“第一个工具”。
7. 候选集合区分“权限禁止”“用户排除”“检索未召回”。前两者不可扩展，最后一种允许一次重新选择。停止在多个模块重新跑关键词 required_deliverables，统一消费 TaskContract。

#### 4.3 子任务完成、重试与纠正

在 AgentState、task.plan_json 和 step.input_payload 中增加版本化子任务账本，优先利用现有 JSON 字段。状态为 pending/running/succeeded/failed/cancelled；包含 subtask_id、attempt、resolved_arguments、artifact_refs、acceptance_result。完成条件为所有必需子任务的实际产物通过验收，不能只看工具返回 success。

当前 ToolRegistry 已用 task_id + tool_call_id 缓存结果；缺陷是完成检查按工具名去重，不能把两者混称为“没有幂等”。保留已有机制，再以 task_id + subtask_id + contract_revision + operation_id 绑定业务副作用，重试重用已落库 operation_id，工具返回缓存与业务操作记录按映射关联。模型新生成 tool_call_id 不应使同一操作再次创建产物。涉及外部 Provider 时不能假设 exactly-once：支持供应商幂等键则传递；否则持久化外部 job ID，恢复时先查状态。状态未知不得盲目重复生成，返回可恢复的失败原因。

瞬时网络错误允许有界重试；参数错误回模型修正一次；权限错误不重试。所有错误保留已成功子任务结果，支持只重跑失败子任务。首版“改成 3 道”“不要了”在下一回合更新草稿/任务契约；执行中的任务沿用既有取消机制，取消确认后再启动修订任务，防止旧任务继续写入。

### 5. 记忆内容模型、召回与上下文

#### 5.1 各类信息的事实源

| 信息 | 存储与权威边界 | 使用方式 |
|---|---|---|
| 当前工作状态 | AgentState、checkpoint、task.plan_json | 本轮目标、子任务、尚未解决问题，不写成学生长期属性 |
| 会话经历 | agent_messages、agent_task_events、learning_records | 原始证据按需检索；保留记录，模型上下文可以压缩 |
| 学生事实与偏好 | student_profiles、student_course_profiles、learning_preferences | 稳定属性由现有 ProfileService 更新；记忆只引用相应版本或补充证据，避免两个可写事实源 |
| 长期学习模式 | student_memories | 有来源的错误模式、适用情境、学习反馈；区分观察和推断 |
| 已生效教学策略 | evolution_strategies | 保留证据、版本、风险审核与回滚；记忆建议不能直接替代策略应用 |
| 课程事实 | 资料切片、知识点、Wiki | 经 RAG/引用链回答知识问题，不复制到私人偏好记忆中 |

新增 MemoryCandidate 契约：candidate_id、memory_type、fact_key、subject_ref、predicate、value、scope、evidence_refs、origin、confidence、valid_until、suggested_action。action 枚举 add/reinforce/supersede/dispute/ignore；最终动作由 MemoryService 决定。证据带 source_type、source_id、observed_at、support/refute 与短引文，ID 必须来自本次实际输入集合且通过用户/课程校验。

语义键使用可读的规范字段，例如 `preference:explanation_style`、`misconception:knowledge-id:dfs_uses_queue`，不由整句自然语言唯一决定。知识点 ID 和错因标签不能匹配时，保留 pending 候选，不把“链表差”和“递归差”合并。后续语义相似度只做候选召回，不能直接据此更新事实。

#### 5.2 写入与冲突处理

- “这次简短一点”只影响本轮；“后面都先给例子”先作为会话内持续偏好；“请记住，我学习时喜欢先看例子”才作为显式长期偏好，通过 ProfileService 持久化并保留证据。含糊的“以后”不自动升级作用域；自动学习的偏好属于可纠正推断，不伪装成用户明确要求。
- 画像工具与 chat_completed 后置提取共用 source_message_id 幂等键；模型回答与检索文本仅作背景，不可归因为学生自述。一个显式修改只能形成一次事实变更，避免同轮工具更新与后台提取相互覆盖。
- “我数学很差”作为自述并标注来源；掌握度仍由已有有效学习证据计算，不能直接下调为低分。单纯提问、浏览次数或模型自己的回答不构成能力不足证据。
- 错误模式至少需要可核对的题目/答案证据；重复引用同一事件不增加 reinforcement_count。增加反证后允许降低置信度、标记 disputed/resolved；不用 max(confidence) 使置信度只增不减。
- 新的显式偏好覆盖旧同作用域偏好，保留 supersedes 关系和变更事件。推断不能覆盖用户明确纠正；课程偏好覆盖该课程内的全局偏好，其他课程仍沿用全局值。
- 只有课程无关且有明确依据的稳定偏好允许进入 global。全局反思禁止直接把跨课程事件拼在一起推断全局弱项；课程删除导致 course_id 置空也不得自动变成全局记忆。
- 无值得记住的信息返回空数组并成功结束，不调用第二个 chat 强行产出。“活跃度高”“请加强复习”等不可操作且缺少具体依据的内容不进入长期记忆。
- 用户归档与容量归档分别标记；增加 forgotten 状态和 tombstone。自动反思不能激活用户归档、忘记或被替代的旧事实；显式 restore 走用户操作并记录事件。忘记同步排除缓存、压缩摘要中的引用和 checkpoint 恢复后上下文，不能只删向量索引。精确抑制与聊天原文保留的边界按第 12.3 节执行，不承诺自然语言任意改写都能自动识别为同一被遗忘事实。

#### 5.3 统一召回服务

拟新增 `MemoryRetrievalService.retrieve(user_id, course_id, query, scene, knowledge_ids, budget)`。内部显式 scope 为 global/course/all_owned；all_owned 只用于本人管理列表，推理召回仅允许当前课程 + global。现有列表 API 的无 course_id 行为兼容保留，新服务不再复用其模糊语义。

先按可信 scope/status/有效期过滤，再利用 query 的知识点、中文规范词/别名和 scene 进行候选召回与排序，最后取最多 50 条进入精排；不能先按 salience 截前 50 再计算相关性，否则低 salience 但与当前问题相关的记忆永远进不来。同一 fact_key 仅返回当前有效版本。先做结构化和词项匹配；新增 embedding 只有在换一种说法的召回评测确实不足时启用，并复用现有 Provider，不加外部向量服务。

现有课程 20/全局 10 的容量限制也必须调整：它们只能作为热记忆数量参考，不代表“其余事实不再可查”。IM-M1 后以 lifecycle_meta.tier 区分 hot/cold，仍有效的 cold 记忆可按需检索；用户归档、忘记、替代、失效一律不可自动召回。历史 reason 不明的 archived 记录不得全部恢复为 cold。health API 新增 hot_count/cold_count/context_budget 明确口径，原 capacity 字段保持旧定义直至页面完成兼容迁移，不静默换义。

起始排序权重可设为相关性 0.50、证据质量 0.25、时效 0.15、salience 0.10；权重属于待调参数。旧记忆相关性不足时可以返回空。默认总数不超过 5、记忆文本预算 1,200 tokens、单条不超过 250；按需提供全局偏好和课程记忆，不能为填满配额注入无关记录。生命周期状态和权限过滤必须在 top-k 之前完成。

返回 memory_id、revision、简短内容、来源、作用域、选中原因。完整证据按 ID 再读取。首版不缓存 query 结果；已有画像缓存须在相关写入后失效。后续缓存键必须包含用户、课程、查询、scene、memory revision，避免跨用户共享召回结果。

Tutor、Resource、Planner、Recommend 与 Runtime 统一调用该服务，PersonalizationContextService 增加 query/scene 参数并保持旧调用兼容。处理器不再各自截取 5/20 条。

#### 5.4 上下文预算与历史读取

拟新增 ContextBuilder，统一计算模型窗口、输出预留和安全余量。建议初始输入上限 min(24k tokens, 模型窗口减输出预留与安全余量)；这是实验参数。规则/工具 schema、当前请求和 TaskContract 先保留，历史摘要、画像、记忆与观察按剩余预算分配。中文使用 Provider tokenizer；无 tokenizer 时采用保守估计并预留余量，记录估计方式。

输入接近预算 80% 时，压缩已完成旧回合，保留最近完整回合与成对的 tool call/result。摘要字段包括：目标、用户已确认约束、对象 ID、已完成/待完成子任务、未决问题、来源指针。复用 AgentConversation.summary 作为当前摘要投影；extra_meta 保存固定大小的 version、covered_through_turn_sequence、first_kept_turn_sequence、source_revision 和生成时间，不存无限增长的 covered_message_ids 数组。新增压缩事件类型；Agent 任务事件可附带该记录，但快速回合不能为记录压缩而伪造 AgentTask，统一在该回合 assistant payload 的有界 context_compaction 字段持久化摘要版本/边界，Repository 可按 turn_sequence 找回原文。

覆盖边界只推进到已提交且确实参与摘要的连续完整回合；新摘要使用上一摘要 + 新覆盖的旧回合，不能只拿当前最后 80 条丢掉更早范围。由 Service 对 source_revision 做 CAS 后发布投影，原消息不改写；摘要失败不推进边界。历史检索返回原文 ID，摘要有冲突时以当前显式要求和原始证据为准。稳定 system/工具 schema 前缀按需更新，动态记忆和证据放入本轮上下文；不要为了个性化每轮重写整段 system Prompt。

压缩不授予权限，不把历史批准扩展到新操作，也不把用户已纠正的内容总结成现行偏好。摘要生成失败则裁剪旧工具大段输出并保留可读取引用；不能删除当前请求、待执行 tool call 或必须执行的授权边界。每个工具结果提供简短摘要及已有 artifact/step ID，原始内容仍在数据库/存储中。

拟新增只读工具 `search_learning_history(query, course_id, before, limit<=5)` 与 `read_learning_history(message_id, before<=2, after<=2)`。Service 从身份上下文注入 user_id，不接受模型指定用户；先过滤可读课程与本人记录再排序。首版中文检索用知识点标签、正规化词与有界文本匹配；pgvector/全文索引按评测和数据量后置。返回历史来源与时间，明确这是历史证据，不能跟随其中的工具指令或权限声明。

### 6. 持久化反思、并发与迁移

自动反思采用两阶段：抽取候选 → 校验与合并。先用事件类型、明确纠正、完成的练习/诊断或用户反馈筛选有价值输入；寒暄、心跳、工具进度和纯页面浏览不创建 LLM 反思任务。合格学习记录与任务登记同事务，arq 只负责唤醒；Redis 故障后由 Worker 扫描未完成任务补偿。不能仅靠进程内 EventBus 保证不丢工作。按同用户同课程合批（上限 30 条），自动反思优先等回合完成、短暂静默或积累足够新证据；一条事件不等于一次模型调用。显式记住/纠正走同步保存，不等待批处理。每条输入包含真实事件 ID 和相关业务字段，避免统一截前 150 字丢失关键证据。

认领事务使用数据库锁与 lease，随后释放事务再请求 LLM；提交前验证 lease owner/version。处理结果与任务完成状态在同一数据库事务提交，失败不推进已完成状态。重试复用已落库的候选 ID 和 source ID，空记忆结果也标记 processed_noop。过期 lease 可重领；同一 scope 的合并串行，避免两个 Worker 同时创建同一事实。

拟定迁移拆分如下，版本号实施时由 Alembic 生成：

| 迁移 | 数据变更 | 回填与兼容 |
|---|---|---|
| IM-M1：事实与生命周期 | student_memories 增加 fact_key（nullable）、origin、revision、lifecycle_meta(JSONB：有效期、归档原因、tombstone、supersedes、tier)；创建 student_memory_events（memory_id、operation_id 唯一、actor、action、before/after、source_refs、created_at）与 student_memory_evidence（memory_id、source_type、source_id、support/refute；来源组合唯一）。同时增加 active fact_key 的 global/course 部分唯一索引，并修复 reflection_states 的 scope 唯一性、增加 memory_revision | 唯一性是新 Writer 上线前置，不得延后选做。旧 memory_key 保留为 legacy key，不盲目语义合并；旧归档默认 legacy_archived 禁止自动复活；旧全局状态合并先留审计，无法判断取舍的重复 active 事实进入待核对。每次增删改/忘记在同一事务推进 scope memory_revision |

### 11. 会话连续性专项：解决“每轮像从零开始”（IM-00）

#### 11.1 重新明确优化目标和原因

用户最直接的需求是：在同一个聊天窗口里，说“再举个例子”“为什么”“第二步没懂”“按刚才的格式”，系统能接着回答。连续体验需要每次模型请求携带必要的历史、当前话题和对象引用；conversation_id、数据库记录、页面聊天气泡本身不会自动成为模型上下文。跨会话学习偏好是另一类能力，可以在会话连续性完成后增强。

本次是静态调用链核查，尚未执行真实多轮复现。以下代码事实可以解释体验，严重程度仍需用多轮探针量化：

| 位置 | 当前事实 | 对连续性的影响 |
|---|---|---|
| GroundedQaPipeline.stream_answer / _answer_without_persistence | 均给 Provider 传 `[ChatMessage(role="user", content=prompt)]`；_build_generation 的变量只有当前 question、检索资料、画像/长期记忆 | 快速问答没有历史 user/assistant 消息；即使传入相同 conversation_id，也仍按单轮上下文生成 |
| GroundedQaPipeline._retrieve | `question=payload.question` | “它和前者有什么区别”直接进入检索，可能找不到正确知识点；只在生成阶段补历史仍不足以解决 |
| agent_runtime/toolsets/learning_tools.py: answer_question | 把 conversation_id 传给 GroundedQaPipeline，但该 Pipeline 没有读取历史；persist_conversation_messages=False 只控制写入 | Supervisor 看过历史，不代表实际回答模型也看过；不能靠 Supervisor 偶尔扩写 question 来弥补 |
| supervisor_prompt.py、graph.py | Supervisor 仅使用最近 12 条消息；graph.run 为每个新任务初始化空 observations/artifacts 等字段 | 当前任务与会话焦点混在一起；新任务重置本身合理，但上一轮产物与约束须另外从会话状态恢复 |
| AssistantPageClient.tsx: sendMessage | 快速路径传现有 conversationId，未统一调用 ensureConversation；use_profile=false | 首轮可能依赖结束后的 done 才拿到会话 ID；profile 关闭确实停用长期个性化，但不应停用同会话历史 |
| GroundedQaPipeline._persist_answer | 会话查找/创建与问答消息写入主要发生在回答完成阶段；_authorize 只校验课程 | 应在读取任何历史和开始模型请求之前校验会话归属、课程和状态；生成失败也应有可追溯用户回合 |
| TutorService._stream_web_search_answer | 仅把当前问题作为 query，结果拼接后写 learning_records，未写会话消息且 done 没有有效 conversation_id | 前端曾显示的联网结果未必能从会话历史恢复，后续“概括第二个链接”缺少目标 |

因此第一阶段应同时打通“历史加载 → 追问检索 → 回答模型输入 → 统一存储”，而不是仅增加 student_memories 的条数。浏览器显示多少条和模型读取多少条应独立配置。

#### 11.2 ConversationContext 契约与接入方式

新增 ConversationContextService（Service 调用现有 Repository），返回内部类型化快照：conversation_id、course_id、request_message_id、context_revision、history_boundary、recent_turns、summary、focus、active_constraints。recent_turns 包含 message_id、role、content、completion_status、引用/产物指针；focus 包含 topic、knowledge_ids、当前资料和最近被讨论的 artifact/version。每项焦点与约束带来源消息 ID。

加载顺序为：认证 → 会话归属/课程/状态检查 → 认领本回合 → 固定历史快照 → 读取已完成回合 → 获取被指代的资料/产物 → 构造模型输入。前端只传请求与选中对象 ID，服务端读取并验证历史，不接收客户端伪造的高权限历史角色。上下文快照存内部状态；对外仅返回简短诊断和当前用户可见 ID。

初始保留最近 6～10 个完整回合，历史预算约 6,000 tokens，仍服从第 5.4 节总预算；按整轮裁剪，不机械取消息数组末尾。历史不足直接使用已有内容；历史超预算再启用摘要，短对话不必多调一次摘要模型。加载本轮之前的数据，当前用户问题仅注入一次；禁止把同一会话中本轮之后新收到的消息混入正在执行的任务。

生成消息结构统一为：可信 system 指令 → 标注为历史背景的摘要/焦点 → 按时间顺序的 user/assistant 历史 → 本轮证据包与用户原始问题。结构化来源信息不可提升历史文本的指令权限。近期正常历史保留原本角色；压缩内容、网页和工具产物明确作为非指令资料；不能将历史助手回答视为已核验课程事实。

GroundedQaPipeline 的流式、非流式使用同一个消息构造函数；Agent answer_question 从服务端 ToolContext 取得本轮 request_message_id/context_revision，加载同一快照。ToolContext 这些字段由 Runtime 注入，不能作为模型可自行填写的 tool arguments。`persist_conversation_messages=False` 的含义仍只是避免重复写消息，与是否读取上下文完全解耦。

关闭画像、RAG 或 Wiki 都不关闭会话历史。优先修复此能力，保留 use_profile 当前产品设置；跨会话长期记忆开关另外控制。新建聊天清空会话短期状态，已有经过允许的长期偏好仍可按设置使用。

#### 11.3 追问消歧、检索与编辑上一轮内容

原始问题始终保留，另生成内部 resolved_query 和 resolution_evidence。例：“解释 BFS”后问“它为什么用队列”，检索 query 补为“BFS 广度优先遍历为什么使用队列”，回答仍针对原始问题。来源记录为上一轮消息和 topic，不把推断出来的条件伪装成用户原话。

优先级：当前显式对象 → 用户在页面选中的资料/产物 → 最近明确焦点 → 必要时语义消歧。“为什么”“继续”存在未完成讲解时继续该讲解；“好”遇到待答澄清时合并草稿；无法唯一确定“第二个”时才澄清。独立新问题更新 focus，不自动拖入旧话题；“这次用英文”只影响本轮，“后面都用英文”成为该会话持续约束，除非用户明确要求跨会话记住。

检索策略分三类：新事实问题使用 resolved_query 重新检索；同主题追问可重读上轮引用的真实 chunk/Wiki 并重新验证；“把上面缩成三句话”“翻译刚才那段”直接读取目标回答做变换，不强制以短句重新搜课程库。变换结果保留原来源状态，旧回答无可靠依据则不升级为已核验。连续例题可以保存已用例子的短摘要，减少同一个例子重复出现。

“讲解上题第 2 个选项”须从已授权 quiz/question 读取真实题干和选项；“修改刚才的课件”须取得原 resource_id/version 和必要内容。只有标题或产物 ID 不足以编辑。将 topic/source_refs/target_refs 从会话快照传到 IM-02 的 TaskContract，以及相关资源/练习 Service；防止问答连续了、生成器仍每次从空主题开始。

普通完整问题采用单次回答生成；显式指代可由对象/主题规则补齐。只有无法可靠解析的短追问或多对象请求才使用一次有界结构化解析；接入 IM-02 后复用其 IntentFrame，不再额外调用另一套解析器。记录解析额外调用数与耗时，避免所有请求都先做一次 query rewrite。

#### 11.4 会话身份、回合持久化与竞态

快速问答、Agent 和联网路径统一先 ensureConversation，再发请求；可通过早期 meta SSE 事件返回 conversation_id/request_message_id，done 再返回最终状态。前端模式切换保持 ID；切课程明确切到该课程会话；新建聊天显式生成新 ID。localStorage 会话键包含 user_id 和 course_id，退出登录清理相关缓存；服务端始终重新鉴权，不把 localStorage ID 视为授权。

已有会话接口可完成首版历史接入，无需立即新增业务表。可靠回合阶段建议新增 IM-C1 migration：agent_messages 增加 client_request_id、turn_sequence、completion_status（pending/completed/failed/interrupted）；agent_conversations 增加 next_turn_sequence、context_revision、active_request_id、active_request_status、lease_owner、lease_until、lease_version。client_request_id 在用户一次发送时生成，流式降级/网络重试复用；旧行字段可空，历史成对成功记录渐进回填，不能把未知中断记录推定为完整答案。该组字段服务于一个原子认领协议，不另建重复的通用调度平台。

在短事务中锁定 conversation，检查/设置 active_request_id、登记 request payload、分配 turn_sequence，并写入 user/pending 后提交；模型调用期间不保持数据库事务锁。对非空 client_request_id 的最终 user/assistant 消息建立 (conversation_id, client_request_id, role) 部分唯一约束；工具事件继续写原有 task/step。相同 request ID 但不同 payload 拒绝为 409，不把用户改问的问题当成重试。首版同会话一次只运行一个回合，第二个不同请求返回可解释的 409；不同会话仍可并行。

lease 在 running 时续租；回合 complete/fail/cancel 与 assistant 状态、context_revision、active_request_id 的释放在一个短事务内完成，必须同时匹配 request ID、owner 和 lease_version。Worker 崩溃后的租约恢复也走 CAS，旧 owner 不得再提交结果；业务写操作检查对应任务/operation 是否仍可执行。外部 Provider 未确认取消时标记 operation outcome_unknown 并查询，不能宣称租约失效就撤销了外部副作用。等待用户安全确认时持久标为 waiting_confirmation，不以普通运行超时自动批准或重复执行；用户须通过既有 resume/cancel 继续，普通新请求明确告知等待状态。

发送前持久化 user/pending，结束后保存 assistant/completed；失败和用户取消写状态，用户输入可在刷新后恢复。中断 assistant 片段不作为完整答案自动带入；用户明确要求续写时可携带标记为 partial 的内容。同一请求重试若仍在运行，返回已有回合的 running 状态；Agent 可重连已有事件，快速路径首版轮询最终状态，不承诺回放尚未持久化的 token 增量。已完成则返回落库结果，不能再次生成并重复写入。SSE 首 token 前降级须共享请求幂等身份；旧请求已确认失败/取消才允许同一回合的新 execution attempt。

为无 AgentTask 的快速回合拟增加 GET `/api/v1/agent/conversations/{conversation_id}/requests/{client_request_id}`，仅返回本人回合状态和已落库最终结果；统一响应。TutorChatRequest、AgentMessageCreateRequest 增加可选 client_request_id，兼容旧客户端由服务端分配。新客户端带 ID 才具备跨连接幂等保障；旧客户端无 ID 的每次请求视为新的发送，不虚称具备重试去重。API Schema 变更纳入 IM-00C 的导出与前端联动。

当前 `AgentTaskRepository.build_task_thread_id` 已生成 conversation_thread_id:task_id，任务级 checkpoint 隔离已经存在。保留并回归验证：resume 同一个任务复用其 thread_id；conversation_id 负责跨回合身份与记忆，不合并不同任务的 checkpoint，不重命名等待确认的历史任务。新任务恢复会话焦点和约束，但不继承上一任务的迭代计数、已批准工具 ID、完成状态或旧副作用。

所有路径复用统一 begin_turn/complete_turn/fail_turn Service；修复联网路径写入会话的缺口。后台任务、前端流式管理模块、快速/非流式降级都使用同一请求 ID。focus/summary 的更新使用 context_revision 比较，迟到的旧请求完成事件不能覆盖新会话或更新版本；删除/忘记相关来源后按第 5 节规则重建上下文。

#### 11.6 专项验收：必须测完整多轮链路

在第 9 节之外增加 30 条连续对话脚本，每条 4～8 轮：快速模式 6、Agent 6、跨模式 6、刷新/恢复 6、切题/切课程/新会话边界 6。另外加入流式中断/非流式降级/同会话并发故障用例；短窗之外再增加至少 3 条 30 轮以上长对话，包含一次话题切换与偏好纠正。

| 对话序列 | 可验证结果 |
|---|---|
| “讲解 BFS” → “它为什么用队列” → “给我一个反例” | 三轮主题连续；第二轮检索包含 BFS/队列；第三轮针对上一论点，不能重新问“你说什么算法” |
| “用 3 个步骤解释递归” → “第 2 步没懂” → “沿用这个例子” | 读取真实第 2 步和原例子，不自行换一个编号/例子 |
| “用 Python 举例，先别给完整答案” → “给个提示” | 遵守本会话约束；没有把限制变成全局长期偏好 |
| Agent 出题 → 快速模式问“第 2 题为什么选 B” → 刷新后“换个解释” | 同一 conversation；真实题目/选项和已答内容可用 |
| 联网找资料 → “总结第二个链接” → Agent “据此出两题” | 可恢复真实搜索结果和目标 URL；来源类型、产物关联正确 |
| 讨论 BFS → “现在解释二叉树” → “它有哪些遍历方法” | 当前焦点已换为二叉树，不继续套 BFS 的旧主题 |
| 新建聊天后“它是什么”或切换课程后引用上一会话对象 | 不默默串用旧短期会话；必要时澄清，显式授权的长期偏好仍按设置读取 |
| 快速 SSE 失败后降级、重复点击、两个窗口同会话发送 | 每个 request 只有一对最终 UI 消息；无重复生成；冲突明确反馈；无未来回合混入 |

增加两级观测：Mock/捕获 Provider 参数断言证明历史、角色和消息边界确实进入最终回答模型；真实模型多轮盲评判断指代正确、约束保持、连续完成任务，不能仅看 messages 数组非空。目标：脚本的会话身份/权限/幂等断言全部通过，真实多轮有效承接率 ≥90%；记录不必要澄清、错误继承旧主题和重复解释率。具体表现以实测报告为准。

短对话历史读取不引入额外模型调用；追问解析、历史检索与摘要分别记录耗时和 tokens。优先达到正确承接，再在相同问题/模型/网络条件下比较首 token 与 p95 完成延迟。验收覆盖快速与 Agent 真实 HTTP/SSE、前端刷新/切换，不把只修 Supervisor 或只修某个后端分支宣称为连续聊天已完成。

#### 12.2 从 harness 借鉴的机制和本项目裁剪

- **Pi 的模型循环和上下文准备**：继续使用 native tool calling，按工具结果决定下一步；不增加一个必须处理所有请求的意图模型。其 [agent-loop.ts](https://github.com/earendil-works/pi/blob/b485fa3128c3d8dae87cb59da6e95db0f991c5bc/packages/agent/src/agent-loop.ts) 还明确拒绝执行因 length 截断而可能不完整的工具参数。智学已有 ChatResponse.finish_reason，IM-02 应检测 length/error/aborted：此响应的写工具零执行，有界重新请求完整参数，而非解析出半段 JSON 就执行。
- **Pi 的压缩边界**：参考 [compaction 实现说明](https://github.com/earendil-works/pi/blob/b485fa3128c3d8dae87cb59da6e95db0f991c5bc/packages/coding-agent/docs/compaction.md) 的保留边界与原文保存。智学采用回合序号记录已覆盖前缀，摘要可重建，不把 token 上限等同于永久删除旧消息；工具调用与结果保持成对。
- **Codex 的记忆筛选与两阶段整理**：其 [Memories 说明](https://github.com/openai/codex/blob/c248f6d48b97eb4a2aa56147a0b11b7d763278b9/codex-rs/memories/README.md) 对合格、静默会话进行后台提炼，有租约、重试与 succeeded_no_output；智学借鉴“有价值才处理”以及提炼/应用分离，不照搬本机文件夹、全局单用户锁和 Git 记忆仓库。项目中的合并锁必须按学生/作用域隔离。记忆写入仍由 Service 管理，不照搬可编辑文件的自由代理。
- **DeepSeek 的事件与投影**：其 [Session](https://github.com/deepseek-ai/deepseek-harness/blob/4878cdabd87d4041bdaff61d04c966883b9fd07a/packages/core/session/README.md) 从会话事件派生模型消息。智学复用现有三类记录：agent_messages 为对话事实，agent_task_events/steps 为执行事实，learning_records 为学习事实；按原始 ID 关联，不宣称目前已经拥有单一全局事件流。ContextBuilder 是读取投影，不能重新成为第四份可独立修改的事实库。
- **Claude Code 的公开循环设计**：按 [官方说明](https://code.claude.com/docs/en/how-claude-code-works) 借鉴收集上下文、行动、验证结果的循环和工具反馈；其公开文档不证明具体内部意图分类或存储实现。智学首版保留显式取消后新开回合，运行中 steering、分支编辑与多 Agent 协同另列增强项。

#### 12.3 一份事实、多种投影，以及“忘记”的准确语义

| 组件 | 唯一职责 | 不承担的职责 |
|---|---|---|
| ConversationContextService | 按用户/课程/回合边界读取原消息、焦点、已确认约束，产出可追溯快照 | 不生成新画像，不判定工具授权 |
| IntentService / TaskContract | 需要时解释本轮语义；明确子任务、对象和交付条件 | 不与 Supervisor 各自维护不同的目标，不把推断当用户批准 |
| ContextBuilder | 为具体模型请求按预算渲染消息；保持来源、角色与协议正确 | 不保存第二份可编辑的原始会话，不悄悄改变任务目标 |
| Supervisor + ToolRegistry | 根据观察规划并执行允许的工具；按子任务验收 | 不负责通用长期记忆写入，不重复生成已完成 QA |
| MemoryService + Repository | 唯一事实写入、证据合并、revision、生命周期和抑制检查 | 不以模型自述置信度取代有效证据，不绕过现有策略审核 |
| MemoryRetrievalService | 在用户/课程过滤后召回当前问题需要的有效事实 | 不因被检索而增加证据强度，不直接修改事实内容 |

同一 ConversationContext 快照可以给 Supervisor 和 QA 渲染不同视图：Supervisor 需要任务/工具摘要，QA 需要原始问题、相关对话和可验证资料。二者共用来源与边界，不能各自再取不同时间点的“最近 N 条”；也不应将整个 Supervisor 状态复制给每个工具。单次请求中相同 retrieved_context/wiki_context 不重复注入全文，按真实来源类型分组。

历史回答中的 `[S1]` 属于历史回合引用，不可直接沿用为本轮 `[S1]`。先解析为真实 source/chunk/version ID，权限和版本重新校验后，分配本轮引用标记；纯改写保留原回答来源状态。过期或已删除来源只能显示历史状态或要求重新检索，不能伪装成新证据。

“忘记此学习记忆”定义为：停止个性化读取、采信和自动重建该事实；保留最小抑制记录（user、scope、canonical fact_key、已知 source_refs、reason、revision），可以存于原 memory 的 lifecycle_meta，不能在 GC 中删除该标记。所有候选先按规范 key 和已知别名检查抑制，再合并；只看 memory_id 不能拦截换 ID 重建。没有可靠规范 key 时，至少阻止已知来源再次提炼，疑似同义候选留待用户明确处理，不自动变 active。

原始聊天是否删除是独立操作，不能把“停用记忆”描述成清除了所有聊天、日志和备份。自动上下文投影应移除由被停用事实派生的记忆摘要、画像标签及关联证据片段；无法可靠局部过滤时重建相关摘要，完成前不注入该摘要。用户主动打开原始聊天仍可查看其原话；若当前明确请求查阅过去内容，可返回标明历史来源的记录，但不能重新激活该个性化事实。掌握度的原始答题记录仍由其自身规则管理，不因停用一句总结而伪改成绩。

该承诺可对有来源/规范 key 的事实做确定性测试；不能保证模型永远不会基于用户重新提供的新内容说出语义相近的一句话。没有显式恢复前，同 key 新证据仍不得自动恢复长期记忆；请求恢复和请求删除聊天分别操作。

#### 12.4 状态一致性、最小上线范围与复审验收

TaskContract 在 task.plan_json 是业务可查的版本化投影，checkpoint 保存执行快照；恢复时核对 contract_revision、task status、已提交 step/operation 结果，不能因 checkpoint 较旧重复执行已落库副作用。数据库完成状态优先，操作结果未知进入核对状态；不声称 PostgreSQL 业务事务、LangGraph checkpoint 和外部服务能构成一个分布式原子事务。

Provider 请求必须保留全部选中的 assistant tool_calls 与一一对应的 tool results；不能只恢复最近一个调用或仅在存在 reasoning_content 时恢复协议。上下文预算不足时丢弃完整已结束工具交换或用有界摘要替代，不保留孤立 tool result；模型返回截断参数不执行。该检查纳入 ContextBuilder 的契约测试，避免记忆增加后破坏模型协议。

最小首版包含：历史真正进入最终模型、快速/Agent/联网统一会话、追问的真实对象绑定、请求幂等和跨用户隔离、现有反思漏记录/重复调用修复。不要求首版完成向量记忆、通用 DAG 调度引擎、每轮 LLM Review、新的跨会话搜索 UI、运行中 steering 或全部 210 个场景。每个阶段先跑对应关键场景，最后完成第 9、11 节的完整评测矩阵。

复审追加用例：①默认值不覆盖课程偏好；②同会话短期约束不写全局；③模型 length 且带 tool_calls 时零写入；④两次压缩保留最早仍有效约束；⑤历史/本轮 `[S1]` 冲突不串来源；⑥同 request ID 不同 payload 拒绝；⑦租约过期旧 owner 不可提交；⑧第 51 条相关记忆可进入候选；⑨超过热容量的有效 cold 记忆可找回；⑩同义 candidate 不绕过忘记抑制；⑪checkpoint 落后于已提交工具结果不重执行；⑫等待人工确认不被租约超时当作同意。

所有准确率、token 配额、top-k 和延迟目标为待校准初值，报告实际分子/分母和场景组，不把小样本 0 次违规解释为普遍安全保证。先在同模型、同场景做无上下文/近期上下文/压缩上下文/加长期记忆的分组对照，分别量化承接能力、错题个性化和不相关记忆干扰，才判断哪一层有收益。本文复审已做文档和源码核对，本轮已记录本地迁移、真实 Provider 与页面功能回归；盲测准确率、分组消融及大规模并发仍需独立实验。
