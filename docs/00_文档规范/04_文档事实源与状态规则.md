# 04_文档事实源与状态规则

> 生效日期：2026-06-06
>
> 目的：防止把早期设计蓝图误认为当前已实现能力。

## 文档状态

项目文档分为三类：

| 状态 | 含义 | 使用方式 |
|---|---|---|
| 当前实现事实源 | 由代码、OpenAPI、ORM、迁移和实际验收反向整理 | 可用于判断当前存在什么 |
| 设计约束 | 规定安全边界、分层原则、实现规范 | 新增与修改功能时必须遵守 |
| 规划参考 | 早期方案、增强版设想、比赛表达材料 | 不得据此宣称功能已实现 |

## 事实源优先级

维护现有项目或判断完成度时，按以下顺序取事实：

1. 当前分支代码与运行结果；
2. Alembic migration 与 SQLAlchemy Model；
3. FastAPI OpenAPI、`16_当前实现API清单.md`；
4. `docs/当前实现基线.md`、`README.md`、真实验收记录；
5. 设计文档与 PRD。

设计文档仍用于约束“应该怎样实现”，但不能覆盖“当前代码实际是什么”。若设计与实现冲突，应先记录差异，再决定改代码还是改设计，不得凭文档虚构接口、页面或数据表。

## 当前事实源入口

- 当前实现总览：`docs/当前实现基线.md`
- API：`docs/11_API接口设计/API接口设计.md`
- 完整 API：`docs/11_API接口设计/16_当前实现API清单.md`
- OpenAPI JSON：`docs/assets/api/openapi-current.json`
- 数据库：`docs/10_数据库设计/15_当前实现数据库清单.md`
- 前端：`docs/12_前端页面设计/01_前端页面总览.md`
- 完成度：`docs/功能完成度与待完善清单.md`
- 真实验收：`docs/19_测试方案/13_真实LLM主链路与Next安全专项验收记录.md`

## 同步要求

修改 Router、Schema 或 SQLAlchemy Model 后执行：

```powershell
python scripts/export_implementation_docs.py
```

每个阶段收尾时同步更新当前实现基线和完成度清单。旧设计方案不要求删除，但必须明确其“规划参考”属性。
