## 文档定位

文档用于解释当前实现、约束后续开发和保留验收证据。不得用早期蓝图覆盖代码事实，也不得用实现现状反向删除仍有效的产品约束。

## 命名与状态

- 目录使用 `NN_主题`；目录总文档与目录同名。
- `当前实现事实源` 可用于判断系统当前能力。
- `目标设计` 描述仍需实现的方向；`历史规划参考` 不能当作已完成能力。
- 验收记录保留具体日期、命令、Provider 和结果。

## 项目术语

| 术语 | 当前含义 |
|---|---|
| LLM Wiki | 有来源、版本、关系和学生编辑能力的学习知识空间 |
| 自进化 | 受控更新画像、记忆、学习策略与推荐策略，不修改代码 |
| Agent | 具有明确输入输出边界的任务执行器，由 Orchestrator 编排 |
| 当前实现基线 | 对当前页面、接口、数据和缺口的事实性摘要 |
| Stitch 页面 | `frontend/public/stitch-pages` 中由 `StitchFrame` 承载的学生端页面 |

## 维护流程

1. 修改 Router、Schema 或 Model 后运行 `python scripts/export_implementation_docs.py`。
2. 功能完成后更新当前实现基线、功能完成度和对应验收记录。
3. 新文档优先补进目录总文档；只有持续独立维护的事实清单或验收证据才新建文件。
4. 提交前扫描空文档、断链、事实冲突并运行 `git diff --check`。
